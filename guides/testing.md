# Testing

This guide shows how to run the library's own test suites and how to
test your handler end to end with an in-process server and the
client. You need it before sending a change, and whenever you want a
fast check that your agent behaves on the wire.

## Run the suites

```bash
rebar3 eunit                       # unit tests, one module per src module
rebar3 ct                          # end-to-end, schema and JSON Schema suites
rebar3 ct --suite=test/barrel_a2a_e2e_SUITE --group=rest
make check                         # fmt compile lint xref dialyzer eunit ct
```

`barrel_a2a_e2e_SUITE` starts servers on `port => 0` and runs every
case in the groups `jsonrpc`, `rest`, `rest_tenant` and `tls`
(self-signed certificates generated by `barrel_a2a_test_tls`). It
covers discovery and caching, blocking and streaming sends, direct
messages, artifacts of every part kind, cancellation, failures and
crashes, follow-ups, out-of-band resume, listing with filters and
scoping, extended card, extensions, version errors, disconnects,
push notifications with a webhook receiver, SSRF rejection, media
type checks, malformed requests and signed cards.

## Schema vectors

`barrel_a2a_schema_vectors_SUITE` validates every JSON example of
the specification, plus hand-written instances for types without one,
against the vendored `a2a.json` (`test/schema_vectors/1.0.1`). It
also proves `priv/schema/a2a.json` is the vendored bundle and that
every `$defs` entry has a vector.

`barrel_a2a_json_schema_SUITE` runs the official
JSON-Schema-Test-Suite (vendored under `test/json_schema_suite`, see
its `VENDORED.md`) against `barrel_a2a_jsonschema`, with remotes
served from memory since a validator must never fetch a `$ref` over
the network.

## Python interop

The interop target runs this library against the reference
`a2a-sdk` (Python 1.1.x, pinned in `test/interop/requirements.txt`):

```bash
make interop-setup    # creates test/interop/.venv, idempotent
make interop-python   # INTEROP_PYTHON=<venv python> rebar3 ct --suite=test/barrel_a2a_python_interop_SUITE
```

The suite skips when `INTEROP_PYTHON` is unset, so a plain
`rebar3 ct` needs no Python. CI runs it on OTP 28 with Python 3.12.

## Examples

```bash
make examples-setup   # _checkouts symlinks so examples build against this tree
make examples-test    # rebar3 ct in each examples/* directory
```

## Test your own handler

Start a server on a free port in `init_per_suite` and drive it with
the client; no mocks are needed.

```erlang
-module(my_agent_SUITE).
-include_lib("common_test/include/ct.hrl").
-include_lib("eunit/include/eunit.hrl").
-export([all/0, init_per_suite/1, end_per_suite/1, answers/1, streams/1]).

all() -> [answers, streams].

init_per_suite(Config) ->
    {ok, _} = application:ensure_all_started(barrel_a2a),
    {ok, Server} = barrel_a2a_server:start(my_agent:card(), #{
        handler => my_agent,
        http => #{port => 0},
        blocking_timeout => 5000
    }),
    [{server, Server} | Config].

end_per_suite(Config) ->
    barrel_a2a_server:stop(?config(server, Config)).

answers(Config) ->
    {ok, Agent} = barrel_a2a_client:connect(barrel_a2a_server:url(?config(server, Config))),
    {ok, {task, Task}} = barrel_a2a_client:send(Agent, <<"hello">>),
    ?assertEqual(completed, barrel_a2a_task:state(Task)),
    [A] = barrel_a2a_task:artifacts(Task),
    ?assertEqual(<<"hello">>, barrel_a2a_artifact:text(A)).

streams(Config) ->
    {ok, Agent} = barrel_a2a_client:connect(barrel_a2a_server:url(?config(server, Config)),
                                            #{prefer => [rest]}),
    {ok, RT} = barrel_a2a_client:start(Agent, <<"long job">>),
    ok = barrel_a2a_remote_task:stream_to(RT, self()),
    Kinds = collect(RT, []),
    ?assertMatch([task, status_update | _], Kinds),
    {ok, Final} = barrel_a2a_remote_task:result(RT, 5000),
    ?assertEqual(completed, barrel_a2a_task:state(Final)).

collect(RT, Acc) ->
    receive
        {a2a_event, RT, Ev} -> collect(RT, [barrel_a2a_event:kind(Ev) | Acc]);
        {a2a_done, RT, _} -> lists:reverse(Acc);
        {a2a_error, RT, E} -> ct:fail(E)
    after 5000 -> ct:fail(timeout)
    end.
```

Run both bindings by connecting twice with `prefer => [jsonrpc]` and
`prefer => [rest]`. For TLS pass `http => #{port => 0, tls => #{...}}`
on the server and `transport_opts => #{ssl_options => [{cacertfile, Ca}]}`
on the client.

## Test push notifications without a network

Pass an `http_post` fun in `push_notifications` to capture deliveries:

```erlang
Self = self(),
{ok, Server} = barrel_a2a_server:start(Card, #{
    handler => my_agent,
    push_notifications => #{
        ssrf_guard => false,
        http_post => fun(Url, Headers, Body) ->
            Self ! {push, Url, Headers, Body},
            {ok, 200}
        end
    }
}).
```

Or run a real receiver on h1 the way `barrel_a2a_test_agent:webhook_server/1`
does and decode with `barrel_a2a_webhook:receive_notification/3`.

## Test the engine without sockets

`barrel_a2a_http_engine:handle/6` accepts any responder map, so a
fake one collecting `{Status, Headers, Body}` in the test process
exercises routing, bindings, errors and streaming with no listener:

```erlang
{ok, Server} = barrel_a2a_server:start(Card, #{handler => my_agent, listen => false,
                                               url => <<"http://test">>}),
Config = barrel_a2a_server:engine_config(Server, #{}),
Self = self(),
Responder = #{
    reply => fun(S, H, B) -> Self ! {reply, S, H, iolist_to_binary(B)}, ok end,
    stream_start => fun(S, H) -> Self ! {stream_start, S, H}, ok end,
    stream_chunk => fun(D) -> Self ! {chunk, iolist_to_binary(D)}, ok end,
    stream_end => fun() -> Self ! stream_end, ok end,
    disconnected => fun(_) -> false end
},
ok = barrel_a2a_http_engine:handle(<<"GET">>, <<"/.well-known/agent-card.json">>, [], <<>>,
                                   Responder, Config),
receive {reply, 200, _, CardJson} -> ok end.
```

## Notes

- `rebar3 ct` needs no network; the push tests use a local h1
  webhook and the SSRF test only resolves `localhost`.
- Set `task_ttl` low in suites that create many tasks, and prefer
  `blocking_timeout => 5000` so a stuck handler fails fast.
